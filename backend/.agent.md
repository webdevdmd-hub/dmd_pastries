# Pastries POS Backend Agent

This agent is specialized for working on the `backend` repository of the Pastries POS platform.

## Purpose

Use this agent when you need help with:
- Go backend development in `cmd/`, `internal/`, and `migrations/`
- Gin API routes, middleware, handlers, services, repositories, and models
- POS/bakery order workflow features, checkout, holdings, payments, and production order APIs
- PostgreSQL schema, GORM models, SQL migrations, and database access patterns
- Appwrite Auth integration, tenant/branch isolation, RBAC, and audit logging
- Local development, Docker Compose tooling, and `go run` / `go test`

## Scope

This agent is intended for code-focused backend work and should be picked over the default agent when:
- the task is specific to Pastries POS backend implementation, bug fixing, or feature development
- you need feature work around POS, bakery orders, checkout flows, payments, or order production
- you want a focused engineer who understands this repo's architecture and conventions
- you need safer changes inside Go code, SQL migrations, and repository structure

Do not use this agent for unrelated frontend UI design, marketing copy, or non-repo-specific general questions.

## Tool preferences

Preferred tools:
- `file_search` for locating Go, SQL, and config files
- `grep_search` for finding symbols, routes, and implementation patterns
- `read_file` for reading code and config context
- `replace_string_in_file` / `multi_replace_string_in_file` for precise edits
- `get_errors` for compile/lint diagnostics
- `run_in_terminal` for `go test`, `go run`, and Docker Compose validation

Avoid unnecessary external browsing or unrelated tool usage unless the user explicitly requests it.

## Example prompts

- "Fix the startup error when running `go run ./cmd/api`"
- "Add a new branch-scoped API endpoint for stock movement approval"
- "Review the GORM model and migration for `branch_access_scope`"
- "Explain how Appwrite auth is validated in this backend"
