Design system v3 · token layer applied

Monochrome by default. Color means money.

One token set, two densities. The counter and the ledger are different jobs, and only spacing, type size, and tap target change between them. Every contrast value below was measured, not estimated.

Typography

Geist for the interface, Geist Mono for money at the counter and every identifier, Fraunces for the wordmark and threshold surfaces. Tracking tightens as size grows and never goes positive.

Weight 500 is the workhorse. 400 for body and table cells, 500 for labels, buttons, product names, KPI values, totals and table headers, 600 for page titles only. Nothing above 600 exists in the system. The current build uses font-black 78 times, which is why everything shouts and the total does not stand out.

Color

Barely-warm neutrals carry every surface. The only saturated things on a screen are the action that takes payment, the thing that warns you, and the thing that broke. Toggle dark mode above — every value below is redefined, not inverted.

Dark mode is not an inversion. Measured on a dark card, v2's four semantic text values score 2.32, 2.26, 2.43 and 2.46 against a 4.5 floor — every one fails. Dark redefines each pair: money #2FAE71 (6.50), danger #F87171 (6.66), warning #E0A030 (8.11), info #7DB3F7 (8.48). The money fill is the exception: white on #00723B is 6.05 on any surface, so the Charge button does not change.

Threshold register

Login pairs the form with the ledger motif: a running total that resolves once to a balanced figure and holds. No loop, no blur, no drift. It respects reduced-motion by rendering the final frame directly.

Components

Buttons

Sizes: sm 32, default 36 (Ledger), lg 44, counter 48. There is no filled secondary; a muted fill and an outline do the same job.

Status badges

Paid Expiring Void Pending Draft

The dot carries the meaning for colour-blind users. Draft is deliberately neutral: it is the absence of a state, not a state.

Empty states

147 routes, and a trial tenant sees almost all of them empty. An empty screen is the first impression of every module, so it is a designed surface, not a fallback. The two registers get different treatments.

Ledger — instructive

No journal entries yet

Entries post here automatically when you record a sale, receive a purchase, or run production. You can also post one by hand.

Counter — terse

Cart is empty

Tap a product to start an order.

The rule. A Ledger empty state names what will fill it, why it is empty, and the one action that changes that. A Counter empty state is one line and nothing else, because the cashier is not reading. Neither uses an illustration.

Motion, elevation, radius

Motion

  • Tap feedback: 0ms.
  • Hover, focus, colour: 150ms cubic-bezier(.2,0,0,1).
  • Panel, dropdown, dialog: 200ms, same curve.
  • Anything blocking a tap: 0ms.
  • Never animate a number changing.
  • The global scroll-behavior: smooth is removed; it currently fights the cashier on every flick through the POS grid.

Elevation and radius

  • --radius-sm 6px chips and badges, --radius 10px buttons, cards, inputs, --radius-lg 14px dialogs and frames.
  • Three shadows only: xs for a segmented thumb, sm for card hover, md for dialogs.
  • Fills over borders. Reserve borders for structural boundaries.
  • shadow-workspace and its inner white bevel are retired; it is invisible on any non-white surface.

Accessibility floor

  • Body text ≥ 4.5:1, large text ≥ 3:1. Every value in this page was measured in both modes.
  • No text below 12px, in either register.
  • Counter tap targets ≥ 48 × 48.
  • Visible ring on every focusable element: #3072C1 light, #7DB3F7 dark, 2px at 2px offset.
  • Colour is never the only carrier of state; every badge has a dot.
  • Semantic solid values are fills, never text. Use the -text pair.
  • foreground-disabled is placeholder and disabled state only, never content.
  • prefers-reduced-motion is respected, including by the login motif.
